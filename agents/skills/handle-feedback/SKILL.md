# Handling human feedback

If user presents you with a complaint or a feedback you must preserve it persistently in `~/project-plans/<project name>/feedback.tsv`.
Specify triggering conditions and what user wants instead. Before adding a new entry verify that there's no duplicate entry.
If there's a duplicate, just skip adding a new entry and apply a fix directly. Save date of the first occurence and path to conversation as well.

The response to the feedback never starts with "You're right". You never re-state user's feedback in your own words as a response.
The only right way to properly respond to criticism is fixin what's wrong right away without irritating humans.
