# Visual explanations

Choose a visual when it answers the reader's question more clearly than prose. A single diagram can explain a complete flow. Use a sequence of diagrams when revealing the parts gradually makes a difficult system easier to follow.

Use a code-native diagram for software relationships when precise labels matter. Use a visual mockup for spatial behavior such as layout or scrolling. Generate an image when an illustration materially helps. Do not require image generation for every spatial explanation.

Keep labels short, show the relevant state or data movement, and explain how the visual connects to the question. A single fact or simple mechanism may need no figure.
